# نسخه ۱.۶.۱ — هماهنگی GitHub Release و وردپرس

## علت ایراد ۱.۶.۰

در تاریخ ۲۲ اکتبر ۲۰۲۶، GitHub Release با تگ `v1.6.0` منتشر شد، اما **خود فایل `gravity-form-custom-view.php` در آن تگ** دو مقدار `Version: 1.5.11` و `GFCV_PLUGIN_VERSION = 1.5.11` داشت. وردپرس پس از نصب بر مبنای هدر فایل، همچنان ۱.۵.۱۱ نشان می‌داد و آپدیتر با تکیه بر تگ ۱.۶.۰، آپدیت تکراری پیشنهاد می‌کرد.

**تگ منتشرشده را جابه‌جا نکنید.** نسخه اصلاحی `1.6.1` باید از آخرین commit شاخه `main` پس از ادغام Pull Request ساخته شود.

## اصلاحات

- هدر اصلی و ثابت برنامه هر دو `1.6.1` هستند.
- آپدیتر قبل از پیشنهاد نصب، آخرین تگ منتشرشده را با **هدر و ثابت نسخه در همان تگ** با API GitHub بررسی می‌کند. در صورت اختلاف، بسته نادرست به وردپرس پیشنهاد نمی‌شود و دلیل خطا برای مدیر نمایش داده می‌شود.
- بسته از `zipball_url` همان تگ معتبر دانلود می‌شود، نه یک ZIP پیوست‌شده که ممکن است قدیمی باشد.
- کش موفق GitHub از ۶ ساعت به ۱۵ دقیقه کاهش یافته است.
- WP-Cron بررسی به‌روزرسانی را حدوداً ساعتی انجام می‌دهد، مشروط به اجرای ترافیک/cron سایت؛ تضمین دقیقه‌ای وجود ندارد.
- دکمه «بررسی فوری به‌روزرسانی» در صفحه نخست افزونه، کش GitHub و `update_plugins` وردپرس را پاک می‌کند و فوراً بررسی جدیدی انجام می‌دهد. این دکمه فقط برای مدیر دارای مجوز `update_plugins` کار می‌کند و **افزونه را خودکار نصب نمی‌کند**.
- GitHub Actions هنگام push شدن تگ یا منتشرشدن Release تطابق شماره نسخه با هدر و ثابت را کنترل می‌کند و در صورت خطا بررسی قرمز خواهد شد.

## مراحل انتشار ۱.۶.۱

۱. پس از Merge، یک GitHub Release **جدید** با تگ `v1.6.1` از آخرین commit `main` ایجاد و منتشر کنید. صرف تغییر نام Release یا ایجاد تگ `v1.6.0` روی فایل قدیمی مشکل را برطرف نمی‌کند.

۲. برای سایت‌هایی که هنوز آپدیتر **۱.۵.۱۱** دارند (کش ۶ ساعته)، بعد از انتشار ۱.۶.۱ در ریشه وردپرس این فرمان را اجرا کنید:

```bash
wp eval 'delete_transient("gfcv_github_latest_release_v1"); delete_transient("gfcv_github_latest_release_v2"); delete_site_transient("update_plugins"); wp_update_plugins();'
```

سپس بخش «افزونه‌های نصب‌شده» را تازه‌سازی و به ۱.۶.۱ آپدیت کنید. می‌توانید به‌جای WP-CLI، ZIP تگ درست را یک‌بار به‌صورت دستی از WordPress > Plugins > Add New > Upload Plugin نصب/جایگزین کنید.

۳. از نسخه ۱.۶.۱ به بعد، دکمه «بررسی فوری به‌روزرسانی» داخل صفحه نخست افزونه در دسترس است.

## نکات فنی

- دریافت Release به اتصال HTTPS سرور وردپرس به `api.github.com` وابسته است. تأخیر یا مسدودشدن API با کاهش کش حل نمی‌شود؛ دکمه بررسی فوری، پیام خطای قابل‌مشاهده ارائه می‌کند.
- GitHub API عمومی محدودیت تعداد درخواست دارد؛ بررسی خودکار به‌صورت ساعتی است.
- WP-Cron در سایت‌هایی با بازدید کم یا `DISABLE_WP_CRON` فعال ممکن است اجرا نشود؛ Cron واقعی هاست توصیه می‌شود.
- ابزار CI و کنترل تطابق نسخه تنها برای تگ‌هایی که پس از افزودن این workflow ایجاد/منتشر می‌شوند عمل می‌کند.
- تست واقعی WordPress نصب، دسترسی شبکه و بروزرسانی آنی روی سرور مشتری انجام نشده است.
