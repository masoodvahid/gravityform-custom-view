# نسخه 1.5.11 — رفع مشکل گزارش پیامک‌ها و ارسال آزمایشی

## علت و رفع مشکل

### دکمه «گزارش پیامک‌های ارسالی»
- در نسخه 1.5.10 پنل گزارش با ویژگی HTML `hidden` بسته بود و بازشدنش کاملاً به JavaScript وابسته بود. اکنون پنل از عنصر بومی `<details>` استفاده می‌کند: هم دکمه بالای صفحه و هم عنوان خود گزارش آن را باز می‌کنند.
- در صورت بسته‌شدن/بازشدن، اسکریپت گزارش را بارگذاری می‌کند. پس از بازشدن، «نمایش گزارش» اطلاعات را مجدد از API می‌خواند.
- `latestoutbox` و `selectoutbox` با `sender=0` (تمام فرستنده‌ها) درخواست می‌شوند؛ پاسخ‌ها، کد HTTP و خطاهای شبکه با پنهان‌سازی API Key نمایش داده می‌شوند.
- اگر کلید سراسری کاوه‌نگار هنوز ثبت نشده باشد، بالای داشبورد هشدار همراه با لینک مستقیم به تنظیمات دیده می‌شود؛ با کلیک روی لینک، آکاردئون تنظیمات نیز باز می‌شود.
- پیامک‌های `verify/lookup` ممکن است در خروجی «sms/latestoutbox» کاوه‌نگار مانند سایر پیامک‌ها قابل مشاهده نباشند؛ مرجع این گزارش کل حساب کاوه‌نگار است.

### «پیش‌نمایش ارسال می‌شود ولی SMS واقعی ارسال نمی‌شود»
- پیش‌تر ساخت بلیت ارسال واقعی فقط هنگامی مجاز بود که متن پترن و بدنه پیام دقیقاً با نسخه ذخیره‌شده برابر باشند. این موضوع بعد از ویرایشِ هنوز ذخیره‌نشده، باعث پنهان شدن دکمه ارسال می‌شد.
- اکنون مدیر کل می‌تواند حتی پیش از ذخیره تغییرات، متن و شماره تستی را بررسی کند؛ یک بلیت یکبارمصرف سرور با عمر پنج دقیقه برای **همان** شماره، فرم، نام پترن و مقادیر پارامترها ساخته می‌شود.
- ارسال **خودکار** انجام نمی‌شود: بعد از پیش‌نمایش، باید «تأیید نهایی و ارسال واقعی» انتخاب و ارسال هزینه‌دار تأیید شود.
- بلیت پس از استفاده حذف می‌شود و محدودیت یک تست در دقیقه همچنان برقرار است.
- متغیرهای Gravity Forms حالا به متن واقعی بدل می‌شوند؛ شامل `{entry_id}`، فیلدهای معمولی و زیرفیلدهای ترکیبی مانند `{1.3}`. دیگر از HTML مربوط به چاپ گزارش برای ساخت پیامک استفاده نمی‌شود.
- پاسخ موفق کاوه‌نگار اکنون با «درخواست ارسال پذیرفته شد» و در صورت وجود با `messageid` نمایش داده می‌شود. تحویل قطعی به گوشی، نتیجه‌ای جدا از پذیرش API است.
- در فهرست رکوردها هم وضعیت واقعی پاسخ سرور و خطای HTTP نمایش داده می‌شود؛ در نبود کلید API، دکمه ارسال غیرفعال است.

## انتشار و تست
پس از Merge، GitHub Release `v1.5.11` را منتشر و افزونه را روی وردپرس به‌روزرسانی کنید.
1. تنظیمات سراسری کاوه‌نگار را چک کنید؛ کلید باید «ثبت شده» باشد.
2. دکمه گزارش پیامک‌ها را باز کنید؛ «۱۰۰ پیام اخیر» را بزنید و در صورت خطا پیام ارائه‌شده را بررسی کنید.
3. در ویرایش لیست، یک شماره تست متعلق به خودتان وارد کنید، از پترن موجود پیش‌نمایش بگیرید و «تأیید نهایی و ارسال واقعی» را کلیک کنید.
4. در فهرست ثبت‌نامی‌ها نیز «پیامک مدیر/کاربر» را بررسی و ارسال واقعی را جداگانه تأیید کنید.
5. در صورت ثبت درخواست در کاوه‌نگار ولی نرسیدن پیام، گزارش وضعیت/تحویل و وضعیت پترن تأییدشده را بررسی کنید.

Static QA: تطابق نسخه، مسیر AJAX، وضعیت کلید، سه فایل JavaScript و شناسه‌های HTML بررسی شدند. PHP parser برای رشته نمونه چندمتغیره روی PHP CLI کنترل شد. اتصال به حساب واقعی کاوه‌نگار و اجرای افزونه روی سایت مشتری در این محیط در دسترس نبود؛ پیش از انتشار روی سایت اصلی، تست استیجینگ توصیه می‌شود.
