# v1.5.4 — printable selection controls

The report's Details View HTML contains Gravity Forms merge tags such as `{10}`, rather than real HTML input controls. The plugin resolves these tags when displaying a record.

### How options are printed

- Current `process_template()` already emits static HTML spans for checkbox/radio questions. **No disabled inputs** are generated by the current server-side renderer.
- The print-window JavaScript now also handles older cached or custom markup that contains `<input type="checkbox" disabled>` or `<input type="radio" disabled>`: each control is removed and replaced with printable static text.
- A checked checkbox uses `■`; an unchecked checkbox uses `□`.
- A selected radio uses `●`; an unselected radio uses `○`.
- Selected choices are bold and annotated with `(انتخاب‌شده)`, so meaning survives black-only photocopies.
- This conversion happens only in the print window and does not change the stored entry or saved HTML template.
- The administrator's `show_all_options` setting remains supported. When off, only selected options are rendered by the server.

### Deployment

Release `v1.5.4` from the merged main branch, update WordPress from GitHub, and verify the installed version number under Plugins. The existing three-column monochrome MSTID Details View HTML does not contain disabled inputs and does not need to be replaced for this fix.

### Checks

Tested the JavaScript conversion snippet for syntax via Node.js, verified the MSTID HTML has zero `disabled` declarations and preserves its original 63 distinct merge IDs. A live WordPress/browser print test must still be performed on staging.
